# RO-02: deterministic routing-observation contract parity

## Objective

Make the reviewed routing-observation receipt contract available to the
product-owned router and Manifest bridge trees without adding a runtime
consumer. A source-owned synchronizer copies the canonical TypeScript bytes
into both repository targets and proves their parity. It does not install a
tree, change a launch source, launch a service, call a provider, select a
combo, or publish an event.

## Frozen scope and contract

- The canonical source remains
  package/contracts/routing-observation-receipt.v1.ts. Update its historical
  ownership notice once so it correctly names RO-02 repository consumers;
  generated TypeScript copies contain those exact canonical bytes.
- The only generated targets are
  package/router/contracts/routing-observation-receipt.v1.ts and
  package/manifest-bridge/src/contracts/routing-observation-receipt.v1.ts.
  No adapter, bridge admission, installer fragment, lock, launchd file,
  product consumer, host runtime or generated JSON schema is added here.
- scripts/sync-routing-observation-contract.mjs is the exclusive source
  writer. It uses fixed repository-relative paths derived from its own module
  location, exports a testable injected-root function, and exposes only
  read-only --check (the default) and explicit --write modes. It accepts no
  arbitrary source, target or root path through the CLI.
- Byte equality includes the ownership notice, whitespace, line endings and
  final newline. The source and any existing target must be regular,
  unlinked files; all existing ancestors from repository root must be
  non-symlink directories. Target mode is exactly 0644. Check mode creates,
  chmods and removes nothing.
- Write mode preflights source and both targets before any mutation; creates
  only the two declared missing contracts directories; stages changed output
  with exclusive same-directory temporary files, sets mode after creation,
  and renames only verified staged regular files. Unchanged correct targets
  retain their inode and mtime. A caught second-publication failure attempts
  verified restoration of an already replaced target, while a process crash
  remains an honest detectable partial state for subsequent --check.
- The synchronizer rejects missing/altered source ownership notice, local or
  dynamic runtime imports in the canonical source, source/target symlinks,
  hardlinks, special files, unsafe ancestors, wrong modes, and source/target
  drift with bounded codes and repository-relative diagnostics.

## Test-first execution

1. Write the temporary-root sync tests and run them before the synchronizer
   exists. Retain the missing-module red receipt.
2. Implement check-mode parity first. Prove missing and drifted copies fail
   with no temporary directory, mtime, mode or content mutation.
3. Implement explicit write-mode generation, raw-buffer equality, 0644 mode,
   idempotence and detached runtime import. Then generate the two real
   repository copies through the owning script and check them.
4. Add adversarial source/target/ancestor symlink, hardlink, nonregular,
   wrong-header, bad-CLI and forged-import tests. Exercise a deterministic
   second-publication failure hook and prove first-target restoration plus
   temporary-file cleanup.

## Acceptance criteria

- Both generated repository copies equal the canonical buffer exactly and
  import independently from isolated router/bridge-shaped temporary trees
  that omit the canonical source and sibling package.
- node scripts/sync-routing-observation-contract.mjs --check is read-only and
  succeeds only when both target files and modes match. The same invocation
  from a foreign working directory resolves the product root from script
  location.
- --write repairs only declared targets, rejects all unsafe source/target
  geometry before writes, preserves correct files without replacement, and
  leaves no owned stage artifact after success or injected failure.
- All tests use synthetic temporary roots and source data. No test contacts a
  gateway, database, provider, combo, service manager, Superset/Hands,
  installed state or Organ Console.
