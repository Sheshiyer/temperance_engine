<objective>
Add LAUNCHAGENT record class to the transactional lifecycle system, enabling `temperance install/update/uninstall` to manage macOS LaunchAgents idempotently with health probes, platform gating, and deterministic plist verification.
</objective>

<context>
Phase 3 established the transactional lifecycle (journal, hazards, planner, executor, receipts). The four existing LaunchAgent shell scripts (`scripts/*launchd.sh`) handle plist creation and launchctl load/unload but live outside the lifecycle system. This plan integrates them as first-class LAUNCHAGENT records.

Doctor v2 host section (`host.ts:85-95`) already probes launchd health via `launchctl print gui/uid/label`. The adapter duplicates this pattern (the doctor function is file-local, not exported).

The existing shell scripts become NEVER-SHIP records in a new `fragments/deprecated-scripts.json`.

**Platform gating**: The existing planner uses `isPlatformSupported()` which emits `status: "unsupported"` outcomes for records whose platform list doesn't match the current OS. LAUNCHAGENT records use the same mechanism — `eligibility.platforms: ["darwin"]` — so on Linux they produce "unsupported" outcomes, not thrown errors. This matches the existing pattern exactly.

**Destination resolution**: LAUNCHAGENT records use `root_token: "HOME"` with `relative_path: "Library/LaunchAgents/<label>.plist"`. The executor's existing `ROOT_PATHS` map already resolves `HOME` to `process.env.HOME`. No new root token needed.

**Executor integration**: The executor's class dispatch at `executor.ts:384-402` is an if/else chain on `record.class`. LAUNCHAGENT adds a new branch after REGENERATE. Unlike COPY/TRANSFORM (stage → verify → promote), LAUNCHAGENT's path is: render plist → write plist → `launchctl load`. The executor calls `io.execFile("launchctl", ["load", "-w", plistPath])` for load and `io.execFile("launchctl", ["unload", "-w", label])` for unload.

**Idempotency**: The executor checks `isLoaded(label)` before load. If already loaded, journals a `skipped("already_loaded")` outcome. This is executor-level, not planner-level — the planner emits steps for all eligible records, and the executor detects "already in desired state" at execution time.

**Update diff detection**: On update, the executor reads the installed plist, computes sha256, compares with the rendered plist. If identical, journals `skipped("unchanged")`. If different, unloads → writes → loads → verifies.

**Rollback preimage**: Before overwriting, the executor saves `{plistBytes: Buffer, wasLoaded: boolean}` as the preimage. Rollback restores the prior plist bytes and reloads (or unloads if the prior state was "not loaded").
</context>

## Task 1: LAUNCHAGENT record type + adapter (type: execute)

**Files:** `src/types.ts`, `src/lifecycle/launchagent.ts` (new).

**Action:**
1. Extend `SurfaceClass` union at `types.ts:12` to include `"LAUNCHAGENT"`:
   ```typescript
   export type SurfaceClass = "COPY" | "TRANSFORM" | "REGENERATE" | "NEVER-SHIP" | "LAUNCHAGENT";
   ```
2. Extend `SurfaceRecord` union with `LaunchAgentSurfaceRecord`:
   ```typescript
   export interface LaunchAgentSurfaceRecord extends SurfaceRecordBase {
     class: "LAUNCHAGENT";
     label: string;                    // e.g. "com.temperance.engine.manifest-bridge"
     plist_template: string;           // inline plist XML template with {{bindings}}
     bindings: Record<string, string>; // template variable values
     verification: { method: "plist-sha256" };
     rollback: { policy: "unload-and-restore" };
   }
   ```
   Note: `destination` is inherited from `SurfaceRecordBase`. LAUNCHAGENT records use `root_token: "HOME"`, `relative_path: "Library/LaunchAgents/<label>.plist"`, `ownership: { kind: "exclusive-path" }`.
3. `launchagent.ts` exports:
   - `renderPlist(template, bindings): string` — deterministic plist rendering (simple string replacement of `{{key}}` placeholders)
   - `isLoaded(label, io): Promise<boolean>` — `launchctl print gui/uid/<uid>/label` check via `io.execFile`; returns false on non-zero exit
   - `loadAgent(plistPath, io): Promise<void>` — `launchctl load -w <plist>` (idempotent: no-op if already loaded, checked via isLoaded first)
   - `unloadAgent(label, io): Promise<void>` — `launchctl unload -w <label>` (idempotent: no-op if not loaded, checked via isLoaded first)
   - `probeHealth(label, io): Promise<{healthy: boolean, reason: string}>` — duplicates doctor host.ts pattern: `launchctl print gui/uid/<uid>/label`, parses exit code + stdout
   - `verifyPlist(expectedSha256, plistPath, io): Promise<boolean>` — read installed plist, compute sha256, compare
4. All operations accept `LifecycleIO` as parameter (execFile for launchctl, writeFile/readFile for plist). No direct `child_process` imports.
5. Platform gate: functions that call launchctl check `process.platform === "darwin"` and throw `Error("PLATFORM_UNSUPPORTED")` if false. The planner catches this and converts to `status: "unsupported"` outcome (matching existing pattern at `planner.ts:225-234`).

## Task 2: Planner + executor integration (type: execute)

**Files:** `src/lifecycle/planner.ts`, `src/lifecycle/executor.ts`.

**Action:**
1. **Planner** (`planner.ts`): Add `LAUNCHAGENT` to the class dispatch. The existing `isPlatformSupported()` at line 132 already handles platform filtering — LAUNCHAGENT records with `eligibility.platforms: ["darwin"]` will emit `status: "unsupported"` on Linux automatically. No new error code needed. For darwin, create steps: preflight (isLoaded check) → render plist → write plist → load → verify → health probe.
2. **Executor** (`executor.ts`): Add `else if (record.class === "LAUNCHAGENT")` branch after the REGENERATE branch at line ~399. The LAUNCHAGENT execution model:
   - **Install**: Check `isLoaded(label)`. If loaded, journal `skipped("already_loaded")`. If not: render plist from template+bindings, write to `$HOME/Library/LaunchAgents/<label>.plist` via `io.writeFile`, then `io.execFile("launchctl", ["load", "-w", plistPath])`, then verify sha256, then probe health.
   - **Uninstall**: Check `isLoaded(label)`. If loaded: `io.execFile("launchctl", ["unload", "-w", label])`. Then remove plist file via `io.rm`. If not loaded: just remove plist if present.
   - **Update**: Read installed plist via `io.readFile`, compute sha256, compare with rendered. If identical, journal `skipped("unchanged")`. If different: unload → write new plist → load → verify → health probe.
3. **Preimage backup**: Before any overwrite, save `{plistBytes: existingPlistBytes, wasLoaded: isLoadedResult}` to the journal's preimage store. The preimage is a JSON-serialized object (not raw bytes) because it includes the loaded state boolean.
4. **Rollback**: Read preimage. Restore prior plist bytes via `io.writeFile`. If `wasLoaded` was true, `launchctl load -w`; if false, `launchctl unload -w` (in case the failed transaction loaded it).
5. **Idempotency**: Second install on already-loaded agent journals `skipped("already_loaded")` with exit 0. This is executor-level detection — the planner always emits install steps for eligible records.

**Verify:** `bun test package/install-surface/test/launchagent-lifecycle.test.ts 2>&1 | tail -3`

**Acceptance criteria:** Install/uninstall/update/rollback all green on mock IO; idempotent second install journals skip; platform gate produces "unsupported" outcome on linux (not thrown error).
