## Task 2: Port manifest section with parity proof (M2, type: execute)

**Files:** `src/doctor/sections/manifest.ts` (new), `test/manifest-section.test.ts` (new).

**Action:**
1. Port each of the 12 bridge checks (`event-log, activation-policy, active-runs, project-registry, prompt-hooks, bridge-source, bridge-launchd, console-launchd, state-root, bridge-health, omniroute, console-health`) from `package/manifest-bridge/src/doctor.ts` into a section runner emitting full DOCT-03 records. Per-check mapping: `source` = probed component/file, `destination` = probed URL or state path (symbolic form — `$STATE_ROOT/...`, never operator literals), `expected_state`/`actual_state` from the check's detail payload, `condition` via pass→PASS/warn→WARN/fail→FAIL, `reason_code` = stable snake_case of check id outcome, `remediation` carried over from summary text, `evidence` = string[] of serialized detail facts (`DoctorCheck.evidence` is `string[]` per `types.ts`).
2. All IO goes through the `ObservationIO` seam — port sync `existsSync`/`readFileSync` calls to `io.lstat`/`io.readFile`, HTTP probes use `io.fetch`, and the legacy `execFileSync('launchctl', …)` in `checkLaunchd` maps to `io.execFile("launchctl", ["print", …])` (checker M1 — the seam already carries `execFile`). Non-darwin launchd checks emit plain `WARN` exactly as the bridge does today (checker m2: bridge never emits UNSUPPORTED; parity would fail) — `platform !== 'darwin'` branch preserved.
3. Evidence redaction rule (checker M3): every evidence string built from a detail payload passes through a symbolizer that rewrites `$HOME`, state-root, and repo-root prefixes to symbolic form (`$STATE_ROOT/event-log.jsonl`) before entering the record — runtime-built evidence bypasses static grep gates otherwise. The parity harness asserts no evidence string matches `/^\/(Users|Volumes)\//`.
4. Parity test: fixture harness drives BOTH implementations against identical injected IO fixtures (same event logs, same registries, same fetch stubs, same `execFile` launchctl stubs); asserts set-equality of check ids and per-id condition equivalence. This is the M2 gate — do not proceed without green parity.
5. Register the manifest runner in `V2_SECTION_RUNNERS` only (never the v1 registry).

**Verify:**
```bash

  && echo 'FAIL: private pattern' || echo 'manifest section clean'
```

**Acceptance criteria:** Parity test proves identical id-set and conditions vs legacy on shared fixtures; section is fully IO-injectable; zero private patterns.
