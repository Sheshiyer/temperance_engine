**Files:** `schemas/fragment.v1.schema.json`, `src/types.ts`, `src/compile.ts`, `test/profiles.test.ts` (new).

**Action:**
1. `types.ts`: add `export type ProfileId = "minimal" | "full" | "no-voice";`. Keep the existing `eligibility.profiles: string[]` field type (schema constrains values; the TS field stays a string array so the record type needs no structural change).
2. Fragment schema: constrain `eligibility.profiles` items to the four-value enum (`default | minimal | full | no-voice`). CompileError `PROFILE_UNKNOWN` on violation (existing `MANIFEST_SCHEMA_INVALID` path may cover it — either error code is acceptable, test pins which).
3. `compileFragments(inputs, options)` gains `options.profile?: ProfileId`. Filter rule: record IN when `record.eligibility.profiles` includes `"default"` OR includes the selected profile. Omitting the option means NO filtering (current behavior byte-preserved for existing callers).
4. Semantic validation, deny policy, authority checks run on the FILTERED set — a profile must be internally consistent, not merely a subset.
