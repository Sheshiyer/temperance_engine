# Optional standalone organ guard

This package owns a reusable process/memory observation guard and its fixed relative policy. It runs without Noesis, Cambium, a provider, native callback registration or an organ implementation. The executable is an exact source promotion; provenance records its original reviewed commit/hash and the descriptor's declared prose-only normalization.

The module is optional and disabled by default in its descriptor. This source package is not listed in the default installer, copied by the router inventory, registered as a callback, or scheduled. Its presence does not activate a service or grant execution permission. The caller remains responsible for admitting a fixed trusted command; this observer is not a sandbox for arbitrary model-generated tools.

Layout is part of the source contract:

```
bin/te-organ-contain.py
router/module-descriptors/organs.json
```

The policy fixes160MiB tree RSS,120seconds maximum wall budget and24 maximum active descendants, with differentiated per-organ ceilings and downward overrides only. It also holds elevated/unknown host pressure, observes birth-correlated Darwin physical footprint, retains4096 lifetime identities including root plus one bounded overflow/cleanup frame (combined<=8192), and routes catchable cancellation including SIGQUIT through cleanup. Original signal identities are never replaced or pruned. None of these observations establishes provider/account capacity or semantic acceptance.

Python3 with its standard library is required. Darwin uses the fixed libproc/libSystem ABI; Linux uses `/proc` and `/bin/ps`, and explicitly reports physical footprint unsupported. Linux's pre-collector capture allocation remains unbounded. Native filesystem/process metadata syscalls are synchronous and cannot be forcibly preempted. Shared deadlines bound continued work after a syscall returns; an additional fixed0.2second emergency direct-child wait remains. Process-group discovery is observed-lineage correlation, not strict ancestry authentication. Reparenting between samples, SIGKILL and host death can escape this userspace observer.

Fixtures verify source/provenance, unchanged policy structure except basis prose, relative descriptor lookup outside the repository working directory and current test-process birth metadata. The inert CLI uses only an empty Python command and disposable receipt/state; it preflights point pressure and skips when elevated or unknown, and the guard independently repeats admission. Skipped or held CLI evidence is not successful execution evidence. No fixture invokes an organ, provider, callback registration, private memory plane or service. A normal point reading is not a sustained memory canary.

Successful guard receipts keep `semantic_acceptance:false`. Installation, exact native callback/terminal/consumer linkage, task authorization, real capacity and sustained host-memory acceptance require separately reviewed owner evidence.
