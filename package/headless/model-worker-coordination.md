# Pure nonblocking worker coordination v1

This source unit implements only trusted injected callbacks. No actual process/FD/native observation, signal, write, provider or model operation is supplied. It does not invoke the existing blocking capture collector or implement a native supervisor. Build policy remains absent; every authority, containment, cleanup, inference, role, pre-effect and replay flag stays false.

`Coordinator(policy, retained_owner, retained_child, channels, clock=..., cancelled=...)` accepts frozen phase-one scalar records. The original creator reserved the designated payload launch once BEFORE this unit and retained its successful ACK. That provenance is a trusted precondition, not authenticated by these DTOs. No reserve/create/retry API exists; uncertain release cannot cause another launch. Nonce/counter/PIDUIDbirth/deadline remain immutable. Launch slots count process launches, not turns/inference requests.

The closed channel declaration assigns FD4 launchACK input, FD3 launchconfirmation output, FD5 stopped-status input and FD6 release output. These are separate roles, not conflated handoffs; no FD type/direction/framing/capability is verified here. Future actual transport must preserve existing fixed codec bounds and parent-close ownership.

`release(adapter)` requires a closed resource observation of exact original creator/child UIDbirth/parent and actual stopped state, normal pressure, independent RSS/physical ceilings, zero active descendants and bounded lifetime count. It then requires injected parent-channel closure, reobserves and invokes release once. Callback native/source identity is trusted owner input, not actual syscall proof. Failure stays held; no release reattempt.

`step(adapter, capture)` observes resource state before each `capture.step()` call. That seam must perform a single nonblocking bounded capture step, not await a whole capture/terminal promise. The caller schedules steps at nominal intervals at most50ms. Measured gap or callback duration over50ms holds; callbacks are synchronous and cannot be preempted. At most256 successful capture steps are accepted, so this conservative finite profile may hold before the calibration wall limit. There is no internal sleep/event loop or idle busy-loop scheduling guarantee. Capture returns closed pending/completed/failed metadata; completion requires trusted terminal observation, exact int exit0 and explicit final-write acknowledgement, never inference from FIFO EOF. These are injected assertions, not actual Codex writer or semantic completion proof.

All admission/release/capture checks use the original effective deadline minus500ms normal cleanup reserve. Cleanup retains the original deadline; once-only emergency cleanup may capture a separate at-most500ms window after expiry, held/unverified and never executable admission. Injected cleanup_identity must equal the first child birth/UID before injected termination. Unknown identity never authorizes termination. This module supplies no actual signal or exact reaping proof; normal/emergency cleanup receipts remain held regardless of callback outcome. Synchronous callbacks may overrun; no unconditional total wall/resource guarantee follows.

Actual native stopped bootstrap, host-pressure enforcement, finite native inventory integration, periodic resource backend, descriptor lifetimes, bounded capture transport, birth-safe native signals/reap and app-server semantic evidence remain later separately reviewed joins. Any future child fixture requires normal pressure and implemented resource/owner guards first.
