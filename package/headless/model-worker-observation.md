# Pure model-worker observation contract v1

This source bootstrap validates trusted in-process policy, retained-owner and process DTOs and folds injected observations. It performs no process creation, native observation syscall, signal, pipe exchange, filesystem operation or model request. It does not implement a supervisor or enable mapped Build.

`Observer(policy, owner, process, clock=..., cancelled=...)` detaches scalar values into frozen records. `sample(identity_observer, usage_observer)` checks the original creator and direct-child identity around a Darwin V0 usage observation. Successful observations retain the first kernel start value; changed birth, native failure, unsupported physical accounting, cancellation, clock regression or either memory ceiling holds permanently. Receipts expose only finite reasons, counts and memory peaks. Every execution, inference, capacity, containment, cleanup, phase-role, pre-effect and replay flag remains false.

The closed `temperance.model-worker-policy.v1` profile accepts only `metadata-calibration`. Its proposed, unmeasured maxima are ten seconds and 128 MiB independently for RSS and physical footprint. Active descendants must be zero; lifetime identities are at most 256 and snapshot IDs at most 4096. These inventory declarations are validated but not enforced by an inventory implementation in this phase. A Build policy is absent and holds. The organ guard policy remains a separate contract.

`temperance.retained-worker-owner.v1` requires the original creator PID/UID/birth, original nonce, post-ACK counter within a launch limit of four, and unchanged monotonic creation/deadline. The original invocation window is at most 120 seconds. These fields are trusted caller state, not authentication, proof of a successful ACK, execution authority or a turn/inference budget. The effective deadline is the earlier original invocation deadline and original creation plus calibration wall bound; it never renews. There are at most 256 successful samples.

Identity callbacks supply closed PID/UID/birth/state records; usage supplies closed backend/result/RSS/physical/kernel-start/kernel-exit fields. The accepted injected backend label is `darwin-proc-pid-rusage-v0`; no ABI implementation or native accuracy is proven here. Linux physical accounting is explicitly unsupported. Trusted synchronous callbacks are checked before and after but cannot be preempted. Closed scalar DTO validation is not a hostile-object allocation boundary.

No child cleanup is attempted or asserted. Future normal cleanup belongs inside the retained execution deadline; any separately bounded best-effort emergency cleanup must be explicit, cannot extend execution and remains held/unverified without independent evidence. Native identity acquisition, host-pressure admission, stopped-before-exec handoff, resource enforcement, finite native inventory, signals, capture and protocol joins remain later phases. The proposed calibration caps do not establish paid-worker capacity; a fast version probe would not establish that capacity either.
