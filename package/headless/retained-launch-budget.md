# Process-local retained launch budget

`LaunchBudget.create_retained(..., owner_pid=os.getpid())` and `reserve_retained(handle)` are additive library APIs. Existing `create`, `reserve` and CLI receipts retain their nine fields and CLI parent-owner convention. No adapter is installed or joined by this change.

The frozen result exposes an immutable receipt mapping and an opaque handle. Result and handle representations are fixed and redacted; receipt access deliberately retains the existing private nonce. Handles are accepted by exact latest-object identity at their issuing instance. Python private fields/constructors are cooperative conventions, not a hostile-process security boundary. Copying fields, deserializing a receipt or creating a lookalike cannot obtain recognized identity. No serialization, recovery or latest-handle retrieval API is supplied.

One retained invocation per instance is allowed. Intent precedes writer operations; reserve consumes the previous handle before callbacks. The original record, directory identity, owner identity, nonce, lifetime, limit and counter are compared before increment. An internally consistent replacement cannot become the original retained invocation. Existing private record/flock/persist remains the sole writer; process-local retention is acknowledgment continuity, not a second ledger.

A usable result appears only after durability/readback, final pre-close path checks, successful independent descriptor closes, and a retained-only post-close clock/birth/clock freshness fence from the same captured record. This fence performs no record reread and creates no new TTL. Path identity is observed before close; subsequent path stability remains a cooperative boundary, not a universal post-close guarantee. A durable mutation followed by uncertain cleanup, late delivery or lost acknowledgement cannot be retried with a previous handle or inferred from disk. Successful reserve returns a new result; prior handle is spent. Consumers must retain both original counters1 and2 before any downstream creation.

Writer-created TTL remains at most120s and is never renewed. Caller exchange/invocation deadlines are a separate consumer obligation: capture them before create and use the minimum with original record expiry. This API does not enforce or authenticate a supplied caller context. A narrow2s consumer can choose fixed ttl_ms=2000 and a shared nondecreasing clock to prove its earlier original deadline, without assuming equality with hidden record timestamps.

Every receipt keeps execution, capacity and inference authorization false. Source continuity is not cryptographic authentication, native callback delivery, FD/process admission, account headroom or semantic acceptance. Same-UID cooperative and synchronous syscall limits of the existing owner remain applicable. No real/native writer point or operational criterion is accepted here.
