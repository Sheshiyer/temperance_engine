# Injected nonblocking capture step v1

Pure owner-provided stream callbacks; no actual FD/native operation, process, signal, network or model implementation. Existing blocking collector stays unchanged. This seam permits a future supervisor to resource-poll before each zero-wait read step rather than disable monitoring with a whole-capture promise. All receipt authority/containment/cleanup/pre-effect/replay flags remain false.

`CaptureStep(adapter, expected, original_deadline_ns, clock=..., cancelled=...)` receives exactly stdout/stderr/final retained identity tuples(dev,inode,type). They are trusted original-owner metadata, not arbitrary selectable FDs or authenticated capabilities. Keys remain immutable and are rechecked before/after each read and before close. Constructor failure closes every independently known matching original identity; duplicate tokens close once, replaced identities never close. Adapter must implement identity(name), nonblocking read(name,maximum), terminal(), close_keeper(), abort_keeper(), close(name). Synchronous callbacks must return immediately but cannot be preempted; late measured completion holds.

Each explicit `step()` performs at most three reads, zero readiness wait/sleep. Requests are at most16KiB and remaining+1 probe, with limits checked before append: stdout4MiB, newline frame64KiB(excludesLF), stderr1MiB, final256KiB and aggregate5MiB. Bytes returned above requested maximum hold; pending read returnsNone and EOF b''. Partial stdout frames at final completion hold. Framing only, no JSON/UTF8/protocol semantics are validated. Private bounded payloads are available only after completed and copies have post-copy deadline checks; held results clear them. Callback-created allocations lie outside this read-request contract.

Original signed64 deadline and atmost120s initialremaining never renew. Nominal step/callback interval is atmost50ms; late holds. Caller schedules resource observation before steps; no internally running monitor or workerresource enforcement exists. Trusted terminal is a closed exited/exit_code/final_write_completed assertion. Completion requires exact int exit0 plus explicit finalwriteACK, allEOF and no partialframe. Exit0/FIFOEOF alone never grants completion. Prewriter finalEOF remains pending; finalkeeper close occurs once only after trusted terminal, followed by250ms drain inside originaldeadline. On held teardown abort_keeper is a distinct non-completing cleanup action permitted only while retainedfinalidentity matches; it cannot fabricate finalwriteACK. Every independent stream cleanup is attempted despite callback failure; cleanup verification stays false.

`coordination_step()` returns the closed four-field projection expected by pure coordinator capture seam, mapping held to failed. It does not claim nativeCLI final semantics or integrate actual bootstrap/ACK/resource/pipe ownership. Payload data is never included in public receipts. Trusted directory/FD transfer/native nonblocking implementation, finalwriter capability and actual app-server/CLI semantics remain future joins. No Build caps or actual worker acceptance follows.
