# Injected stopped-bootstrap state v1

This helper supplies no native adapter and opens no descriptor, process or transport. It models a single trusted adapter lifecycle for the explicit unmeasured metadata-calibration policy. It does not authorize Build, perform host-pressure admission, prove resource enforcement or enable native execution. Do not connect it to an actual launch until subsequent resource/pressure and original launch-ACK joins are implemented and reviewed.

`Bootstrap(policy, owner, channels, clock=..., cancelled=...)` reuses the closed frozen phase-one policy/owner parsers. Owner nonce, post-ACK counter and original creator PID/UID/birth are trusted retained caller state, not authenticated ACK proof. The effective deadline remains the earlier original invocation deadline and original creation plus calibration wall bound. Admission and every release-path check use this deadline minus a fixed 500ms normal cleanup reserve; insufficient initial remaining time holds. Cleanup itself retains the original effective deadline. No disk read, counter recreation, refund, new nonce or renewed execution deadline occurs.

The proposed closed channel declaration is `temperance.worker-bootstrap-channel.v1`: exactly status_fd=5 (adapter-to-owner stopped-status input), release_fd=6 (owner-to-adapter release output), frame_bytes=16384, aggregate_bytes=32768 and execution_authorized=false. This freezes roles separate from the launch/organ FD3/4 contracts. The unit does not validate real FD direction/type, forward FD capabilities, parse framing, or enforce byte limits; those remain future transport responsibilities.

The trusted adapter API is `observe(pid)`, `create_stopped()`, `close_parent_channels()`, `release(pid)` and `terminate(pid)`. Creator observations have closed pid/uid/birth/state fields. Child observations have closed pid/uid/birth/parent_pid/state/source fields; source must be `adapter-native-observation`, parent_pid the original creator, UID equal and actual state stopped before release. This string is a declaration from trusted owner code, not authentication or evidence that a native syscall occurred. Child self-report and PID alone cannot satisfy the accepted profile. The first accepted child identity is retained and never overwritten. Creation uncertainty consumes the existing launch slot and prohibits another creation call.

`run(adapter)` checks creator identity, obtains the stopped child observation, closes parent channel copies, rechecks creator and exact stopped child, then calls injected release once. Every callback is checked before/after against cancellation and original deadline. Callback exceptions hold with finite redacted diagnostics; failures after known child creation retain cleanup ownership. The caller must explicitly call cleanup; run does not claim automatic cleanup. These synchronous callbacks are not preemptible, so no unconditional hard wall or actual stopped-before-exec proof is established by the state machine alone.

`cleanup(adapter)` is once-only and always held/unverified. Within the original deadline it rechecks creator and child birth before injected termination. If already expired, it captures a separate best-effort emergency deadline once, at most 500ms later, for cleanup only; no release or admission can use it. Unknown/replaced identity prevents termination, and late callback completion remains held. No process-group signal, descendant discovery, actual exit proof, successful cleanup or zero-cleanup assertion exists.

Receipts retain no PID, birth, nonce, raw output or exception text. All execution, capacity, resource containment, cleanup, actual phase role, inference, pre-effect and replay flags remain false. `injected-release-observed` means only the trusted callback returned its success sentinel inside the deadline, not a native launch or execution authorization. Build maxima remain unset; organ policies and private organ handoff ownership remain unchanged.
