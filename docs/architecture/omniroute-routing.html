OmniRoute Routing The live multi-model gateway, governed portfolios, provider lanes, and availability reconciler behind Temperance's automatic routing

Scope. This doc is the OmniRoute reference: the local gateway topology, every governed combo and its strategy, the provider/connection lanes, and the policy-driven reconciler that keeps combos pointed at healthy providers. For the productization narrative see architecture.html; for install mechanics see system-internals.html; for wired-vs-reference seams see integration-map.html. Full prose lives in docs/omniroute-runtime.md, docs/omniroute-fleet.md, docs/omniroute-connections.md, and docs/kimi-surface.md.

1. Local Topology

Client surface (host) Local relay (optional) OmniRoute gateway Upstream provider lanes

Explicit picker models (auto/* or a named te-*/omniroute/* combo) always bypass the relay's classifier and hit OmniRoute directly — only the temperance/temperance-auto model routes through the proxy. If the relay is stopped, direct omniroute/temperance-coding picker entries and the temperance-route / temperance-batch CLI rails keep working.

4. Availability Reconciler

1 · manual-disable (HARD DOWN) Provider is isActive:false via GET /api/providers, or absent from omniroute usage quota while ≥1 other provider is present. Substitution is mandatory regardless of quota.
2 · quota Remaining quota below threshold_percent (30%). A substituted base model only returns once its provider is isActive:true AND remaining ≥ restore_hysteresis_percent (40%) — hysteresis prevents flapping at the boundary.
3 · unknown / no data Priority combos fail open (keep the live model, never switch on missing data). Fusion combos fail closed: verdict HOLD, no mutation, exit code 3, reason recorded in the state file and event log.

Dedup

If two slots resolve to the same substitute, the later slot advances to its next chain entry instead of duplicating the model.

Judge independence

A fusion judge substitute must never equal any post-substitution panel model; conflicting candidates are skipped.

Fusion panel floor

After substitution the panel must keep ≥ max(minPanel, 2) resolvable models, else HOLD.

Tier gating

Tier1 substitutes may land anywhere; tier2 bench models only in trailing/chain-end positions — a tier2 model in slot 0 yields requires-probe (dry-run) or HOLD (apply).

Mutations are full-body PUT /api/combos/:id (OmniRoute has no PATCH), preserving the combo id and every untouched field. Every run that can mutate snapshots {settings, combos, catalog, policy, plan} to .omniroute-backups/omniroute-reconcile-<UTC>.json first — dry-runs included — and the global activeCombo is verified unchanged afterward.

6. Headless Deployment (EC2 Shadow)

A route-only Temperance release can run beside Hermes on EC2 without touching Hermes units, installing a model backend, or granting approval — package/headless is the standalone runtime, fail-closed on unknown fields, missing approval observations, and missing policy routes.

Build

scripts/build-headless-shadow.sh refuses a dirty tree, runs test + standalone:audit + standalone:smoke, emits a typed result (release id, source commit, archive path, SHA-256).

Install

scripts/install-headless-shadow-archive.sh installs idempotently under /opt/temperance-headless/releases/<version>-<commit12> as a dedicated nologin temperance-shadow user — no current symlink.

Key resolution

The Keychain lookup is darwin-only; temperance-openai-proxy.ts also reads OMNIROUTE_API_KEY_FILE (0640, LoadCredential=) so the systemd/Linux relay can supply a gateway key without an env var.

Health

scripts/capture-ec2-shadow-health.sh captures before/after snapshots keyed by a stable session id. Full runbook: docs/runbooks/ec2-headless-shadow.md.
